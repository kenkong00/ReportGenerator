# 深度调研报告生成器

输入一个问题 → 自动拆解 → 联网广泛取证 → 多视角交叉论证 → 产出**每句话可溯源**的调研报告。
对不一致的说法不和稀泥：能裁决的给裁决，不能裁决的明确标为「未裁决」并分析为什么各方的说法会不一样。

## 快速开始

双击 `启动.bat`，浏览器自动打开 `http://localhost:5210`。

首次使用需要配置大模型（否则无法生成报告）：

1. 打开 **设置** 页
2. 填入 API Key（推荐 DeepSeek / 硅基流动 / 通义，都是 OpenAI 兼容协议）
   - DeepSeek: `https://api.deepseek.com/v1` + 模型 `deepseek-chat`
   - 硅基流动: `https://api.siliconflow.cn/v1`
   - 通义: `https://dashscope.aliyuncs.com/compatible-mode/v1`
3. 点「测试连通性」，变绿即成功
4. 回首页，输入问题，点「开始调研」

联网检索**不需要任何 key**：内置 Bing RSS 通道（零 key 实测可用）。

## 报告怎么读

- **三档篇幅**：速览（一屏看懂结论）/ 标准（完整论证）/ 深度（逐节扩写，仅深度模式生成）
- **证据上标**：正文里的 `[A]` `[B]` 等彩色小标可以点，点开能看到原文摘录、来源权威等级、置信度判定依据
- **权威等级**：A 一手权威（政府/统计/交易所/公司披露）· B 专业二手（主流媒体/券商研报）· C 需交叉验证（百科/社区）· U 未知
- **置信度**：由规则引擎判定（≥2 个独立 A 级来源一致才是「高」），模型只能建议降级、不能抬高。标注「存疑」的结论要么有来源冲突、要么是推断——推断会附完整推理链条
- **分歧地图**：专门一节列出各方说法打架的地方，并分析分歧根因（口径差异/时间点差异/利益立场等）
- **调研过程**：点「查看调研过程」可以看到 10 个阶段每一步的原始输入输出 JSON——结论是怎么来的，全程可核对

## 技术要点

- Vue 3 + Vite（5209）· Express 4 + better-sqlite3（5210）
- 流水线跑在 `child_process.fork` 子进程，Express 崩了不影响任务
- 10 阶段状态机：澄清 → 拆解 → 视角 → 检索 → 来源评估 → 证据抽取 → 交叉验证 → 写作 → 装配 → 自审
- 事件全部落库（`stage_events` 表），SSE 断线用 `Last-Event-ID` 自动续传
- 三档报告自底向上装配（共用同一份核心结论），不是「写长文再压缩」，结论天然一致
- 反幻觉机制：模型只能引用系统真实检索到的证据（`[[ev:id]]` 引用校验，无效引用降级为 `[?]`）；模型永不生成 URL
- 预算闸门：检索/抓取/Token/墙钟四项限额，超预算自动降级（跳过低优先级子问题、改用摘要等），降级动作在报告里显式声明

## 已知限制（M1 版本）

- 证据文本主要来自搜索摘要（本机网络下大量英文站点不可达，正文抓取默认关闭；设置里可开，但成功率取决于目标站点）
- 维基百科 / Reuters / Google 本机不可达，英文视角依赖搜索摘要
- 云端免密钥通道（WorkBuddy Cloud LLM）从 Node 后端调用可能被 Origin 校验拒绝，主力通道是自填 API Key
- Tavily/博查/Serper/Brave 专业搜索 API、断点续跑、PDF 解析导入等在 M4/M5 里程碑补齐

## 开发

```bash
npm install        # 安装依赖
npm run build      # 构建前端（改动 src/ 后需要重新 build）
npm run serve      # 只启动后端（托管已构建的前端）
npm run dev        # Vite 开发模式（5209，/api 代理到 5210）
npm run probe      # 环境探针（SQLite/FTS5/Bing RSS 连通性）
```

注意：本机 npm 沙箱环境装依赖需要 `--ignore-scripts`，且要手动补装平台二进制包
（`@esbuild/win32-x64`、`@rollup/rollup-win32-x64-msvc`，版本号分别对齐 esbuild 和 rollup）。
